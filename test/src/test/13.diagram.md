# 完全离线的多语言图表渲染工具技术方案（基于 Rust + Python 混编）

---

## 1. 方案概述

本方案通过**前后端集成 + 多语言混编**，实现你清单中全部 27 种图表工具的**完全离线**渲染，且**无需运行 Kroki 服务**。系统由一个统一的 **Rust 后端服务**（提供 HTTP API 或 CLI）和**前端界面**（Web/Electron）组成，后端负责调度各类图表渲染器：

- **Rust 原生渲染器**（内联集成，无外部依赖）
- **Python 脚本**（通过 `PyO3` 或命令行调用）
- **Java JAR**（通过 `java -jar` 调用）
- **其他原生命令行工具**（如 Graphviz、Dpic、Gnuplot 等）

```sh
# 参考对标
ASCIIToSVG、BlockDiag（BlockDiag、SeqDiag、ActDiag、NwDiag / RackDiag / PacketDiag）、Bytefield-SVG、DBML、Ditaa、Dpic、Erd、Gnuplot、GoAT、Graphviz、LilyPond、Mermaid、MscGen、Nomnoml、Penrose、Pikchr、Pintora、PlantUML、Shaape、State Machine Cat、Structurizr、SvgBob、Symbolator、Syntrax / JSyntrax、UMLet、Vega / Vega-Lite 和 WaveDrom 语法。

Asciidoctor Diagram 的灵感来源于 AsciiDoc PlantUML 过滤器。
```

## 2. 架构设计

```
┌─────────────────────────────────────────────────────────────────┐
│                     前端 (Web UI / CLI)                        │
│        用户输入图表代码 & 类型，请求渲染接口                     │
└─────────────────────────────────────────────────────────────────┘
                              │ HTTP / stdio
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                 Rust 后端 (actix-web / clap)                    │
│              ┌────────────────────────────────┐                │
│              │   Diagram 路由器 & 调度器      │                │
│              │  - 根据类型路由到对应渲染器    │                │
│              └────────────────────────────────┘                │
│         │              │              │              │         │
│         ▼              ▼              ▼              ▼         │
│  ┌─────────────┐ ┌─────────┐ ┌──────────┐ ┌──────────────┐   │
│  │ Rust 原生   │ │ Python  │ │  Java    │ │ 其他命令     │   │
│  │ 渲染器      │ │ 封装    │ │ 封装     │ │ 行封装       │   │
│  │ (内联)      │ │ (PyO3)  │ │ (process)│ │ (process)    │   │
│  └─────────────┘ └─────────┘ └──────────┘ └──────────────┘   │
│      │                 │            │              │          │
│      ▼                 ▼            ▼              ▼          │
│  输出 SVG/PNG 统一返回给前端                                  │
└─────────────────────────────────────────────────────────────────┘
```

**关键设计**：
- **Rust 原生渲染器**：直接集成所有有 Rust/WASM 实现的图表库（如 Mermaid、PlantUML、Pikchr、SvgBob、Graphviz 等），零外部依赖，性能最佳。
- **Python 工具**：使用 `PyO3` 将 Python 解释器嵌入 Rust，或通过 `std::process` 调用 Python 脚本。前者可避免进程开销，但会增加包体积；后者更轻量但依赖系统 Python。
- **Java / 其他工具**：通过 `std::process::Command` 调用系统已安装的命令或打包在应用中的可执行文件。

## 4. 实现策略：精简依赖与打包

### 4.1 选择“轻量级”分发模式（推荐）

- **前端**：采用纯 Web 界面，通过浏览器直接与 Rust 后端通信（HTTP），或制作成单页 HTML + WASM（全前端方案，但无法覆盖所有格式）。
- **后端**：Rust 二进制 + 外部依赖（Python、Java、Node.js 等）作为可选组件。**用户需预先安装** Python 3.8+、Java 8+、Node.js 12+ 以及对应工具包（如 blockdiag、ditaa 等）。  
  然后，在 Rust 中调用这些命令时，检测是否存在，若不存在则返回友好错误提示。

**优点**：Rust 二进制很小（约 10-15MB），依赖由用户环境提供，整个包体积最小。  
**缺点**：用户需手动安装依赖，不适合完全零配置的场景。

### 4.2 完全自包含模式（可选）

- 使用 `py2exe`、`PyInstaller` 将 Python 脚本打包成独立可执行文件，然后随 Rust 后端一起分发。
- 将 JRE 的精简版（如 OpenJDK 的 jre 瘦身版）打包。
- 将 Node.js 的运行时（如 `node` 可执行文件）打包。
- 将所有命令行工具（Graphviz、Gnuplot、LilyPond 等）的 Windows/Linux/macOS 版本打包进 `bin/` 目录。

**缺点**：包体积会膨胀到 **200-400 MB**（含 JRE、Node、Python、各种库）。  
**优点**：用户解压即可用，无需额外安装。

### 5.1 项目结构

```

├── Cargo.toml

│   │   ├── python.rs           # Python 调用封装

│   └── ...

```

### 5.2 核心代码示例

#### 渲染器 Trait

```rust
// src/renderers/mod.rs
pub trait Renderer: Send + Sync {
    fn render(&self, code: &str) -> Result<String, RenderError>;
}

pub struct RenderError {
    pub message: String,
}
```

#### 原生渲染器（Mermaid 示例）

```rust
// src/renderers/rust_native.rs
use mermaid_svg::render as mermaid_render;
use plantuml_little::render as plantuml_render;

pub struct MermaidRenderer;
impl Renderer for MermaidRenderer {
    fn render(&self, code: &str) -> Result<String, RenderError> {
        mermaid_render(code).map_err(|e| RenderError { message: e.to_string() })
    }
}
```

#### Python 渲染器（调用外部脚本）

```rust
// src/renderers/python.rs
use std::process::Command;

pub struct PythonRenderer {
    script_path: String,
    python_exe: String, // e.g., "python3"
}

impl Renderer for PythonRenderer {
    fn render(&self, code: &str) -> Result<String, RenderError> {
        let output = Command::new(&self.python_exe)
            .arg(&self.script_path)
            .arg("--type=blockdiag")  // 或从 code 推断
            .arg("--input")           // 可传入 stdin
            .arg("-")
            .stdin(std::process::Stdio::piped())
            .stdout(std::process::Stdio::piped())
            .spawn()?;
        // 写入 code 到 stdin，读取 stdout 返回 SVG
        // ...
        Ok(svg)
    }
}
```

#### 路由调度

```rust
// src/server.rs
async fn render_diagram(
    web::Json(payload): web::Json<DiagramRequest>,
) -> HttpResponse {
    let renderer = get_renderer(&payload.format);
    match renderer.render(&payload.code) {
        Ok(svg) => HttpResponse::Ok().body(svg),
        Err(e) => HttpResponse::BadRequest().body(e.message),
    }
}
```

## 6. 构建与打包

### 6.1 构建 Rust 后端

```bash
cargo build --release
# 输出 target/release/diagram-tool (约 10-20 MB)
```

### 6.2 打包外部依赖

- 将 Python 脚本复制到 `scripts/` 目录。
- 准备一个 `install_deps.sh` 脚本，自动检测并安装缺失的系统依赖（Python 包、Java、Node 等）。
- 若采用自包含模式，则将需要的二进制文件（`java`, `node`, `python`, `dot` 等）放入 `runtime/` 目录，并设置 `PATH` 环境变量指向该目录。

### 6.3 跨平台注意事项

- 使用 `std::env::consts::OS` 区分平台，提供不同平台的二进制文件。
- 对于 Windows，可能需要提供 `.exe` 后缀。

## 9. 总结

本方案通过 **Rust 主程序 + 多语言外部调用**，实现了**完全离线**且无需 Kroki 服务的图表渲染工具集。核心二进制小而快，外部依赖可按需安装或自包含打包，兼顾了**灵活性**与**精简性**。如果选择轻量模式，最终分发包可控制在 **30 MB 以内**，已具备很好的实用价值。
